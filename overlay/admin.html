처음 사용하는 사람을 위한 설정 안내Beginner setup guide

처음에는 한 번에 여러 값을 바꾸지 마세요. 아래 순서대로 한 항목씩 바꾸고 10초 정도 말해 본 뒤 결과를 확인하면 원인을 찾기 쉽습니다. Change one value at a time, speak for about 10 seconds, and check the result before changing another setting.

1. 최초 설정 순서1. First-time setup

  1. 장치와 프로필: START_HERE의 4번 RTX 40/50 시리즈 자동 설정을 먼저 실행한 뒤 실제 사용할 마이크를 선택합니다. 특정 모델명이 달라도 RTX 40/50 계열이면 이 자동 설정으로 시작하면 됩니다.Device and profile: Run START_HERE option 4 Auto GPU preset for RTX 40/50 Series first, then select the microphone you will use. Start here even if your exact GPU model name is different.
  2. 오디오 탭: VAD 엔진은 Silero, 음성 기준은 0.5, 시작 여유 시간은 0.3초에서 시작합니다.Audio tab: Start with Silero, threshold 0.5, and pre-roll 0.3 seconds.
  3. 자막 탭: 일반 방송은 크기 30~36, 최대 2줄, 한 줄 22~28자로 시작합니다. 대화를 오래 남기려면 저스트 채팅 모드와 8~12줄을 사용합니다. 낮은 지연은 빠른 말 읽기 보호를 0.2초로 시작하고, 위쪽 자막을 더 오래 읽으려면 0.5~0.9초로 올립니다.Caption tab: Start with size 30–36, 2 lines, and 22–28 characters. Use Just Chatting with 8–12 lines for persistent history. Start Fast speech reading hold at 0.2 seconds for low latency, or raise it to 0.5–0.9 seconds for longer reading time.
  4. 실시간 처리 탭: 청크 1.0초, 겹침 0.2초, 갱신 간격 0.3초, 대기열 2를 기준으로 둡니다.Streaming tab: Start with chunk 1.0, overlap 0.2, debounce 0.3, and queue 2.
  5. 저장 후 재시작: 오디오·청크·유행어 설정을 바꿨다면 실행 중인 자막 창을 Ctrl+C로 끄고 START_HERE의 1번 방송 자막 시작을 다시 실행합니다.Restart: After changing audio, chunk, or slang settings, stop the caption window with Ctrl+C and run START_HERE option 1 Start live captions again.

1-A. 방송을 시청하는 PC에서 자막 보기1-A. Caption a broadcast playing on this PC

  1. 입력 소스를 PC 재생음으로 바꿉니다.Set Input source to PC playback.
  2. 방송 소리가 나오는 PC 출력 장치를 선택합니다. 잘 모르겠다면 Windows 기본 출력을 고릅니다.Choose the output device that plays the broadcast. Use the default Windows output when unsure.
  3. 오디오 저장을 누른 뒤 START_HERE의 3번 시청자 PC 재생음 자막을 실행합니다. 저장된 마이크 방송 설정을 바꾸지 않고 이번 실행만 PC 재생음으로 시작합니다.Save Audio, then run START_HERE option 3 Caption PC playback. It uses PC playback for one run without changing the saved microphone broadcast setup.
  4. 마이크와 PC 소리를 동시에 자막으로 만들기: 입력 소스를 마이크 + PC 재생음으로 선택하고 두 장치를 모두 지정합니다. 마이크 증폭과 PC 증폭을 따로 맞춘 뒤 저장하고 방송을 재시작하세요. START_HERE의 9번은 저장값을 바꾸지 않고 듀얼 입력으로 바로 실행합니다.Caption microphone and PC playback together: select Dual input, choose both devices, tune each gain, save, and restart. START_HERE option 9 starts dual input without changing the saved source.
  5. 자막 화면 분리: 통합은 /caption, 마이크만은 /caption?source=microphone, PC 소리만은 /caption?source=system을 사용합니다. OBS 브라우저 소스도 같은 주소를 사용합니다.Separate caption views: use /caption for combined, /caption?source=microphone for mic only, and /caption?source=system for PC playback only.
  6. 같은 문장이 두 번 나오면: 헤드폰을 먼저 사용하고 교차 입력 중복 억제를 켜세요. 이 기능은 비슷한 텍스트를 제거하지만 실제 음향 에코 제거 기능은 아닙니다.If a sentence appears twice: use headphones first and enable cross-source duplicate suppression. It removes similar text but is not acoustic echo cancellation.
  7. 방송을 재생하고 상태의 Input이 system | voice로 바뀌며 RMS 막대가 움직이는지 확인합니다.Play the broadcast and confirm that Input shows system | voice and the RMS meter moves.

선택한 출력 장치로 나가는 모든 소리가 들어옵니다. 방송과 함께 알림음, 음악, 게임 소리도 자막 인식 대상이 될 수 있습니다. 특정 브라우저 한 개의 소리만 분리하는 기능은 아닙니다.All sound sent to the selected output is captured, including notifications, music, and games. This does not isolate one browser or app.

4. 언제 재시작해야 하나요?4. When is restart required?

  • 즉시 반영: 자막 크기, 최대 줄 수, 저스트 채팅 모드, 빠른 말 읽기 보호, 임시·확정 자막 유지 시간Immediate: caption size, maximum lines, Just Chatting, fast speech reading hold, pending and confirmed display times
  • 자막 재시작 필요: 마이크, VAD, 입력 증폭, 문장 분할 길이, 청크·겹침·대기열, 유행어 인식 힌트, 하드웨어 프로필Restart captions: microphone, VAD, gain, sentence splitting, chunk, overlap, queue, slang prompt, hardware profile

  3. START_HERE의 1번으로 재시작한 뒤 10초 동안 평소 말투로 테스트합니다. 그래도 문제가 있으면 6번 검증 또는 7번 분석 묶음을 사용합니다.Restart with START_HERE option 1 and test normal speech for 10 seconds. If the issue remains, use option 6 Validate or 7 Support bundle.

6. 방송 중 검증 화면을 사용하는 방법6. Use the validation screen during a broadcast

  1. 먼저 자막 실행: START_HERE의 1번 방송 자막 시작을 실행한 뒤 상단의 방송 검증을 엽니다. 검증 화면에 `세션 없음`이 보이면 아직 자막 세션이 만들어지지 않은 상태입니다.Start captions first: Run START_HERE option 1 Start live captions, then open Validation from the top bar. `No session` means a caption session has not been created yet.
  2. 문제가 생긴 바로 그 순간 표시: 필요하면 메모에 실제로 말한 문장이나 원하는 단어를 적고 아래 네 버튼 중 하나를 누릅니다. 현재 방송 시간, 마지막 자막, 메모가 함께 저장됩니다.Mark the exact moment: Optionally enter what was actually said or the desired word, then press one of the four buttons. The audio offset, latest caption, and note are stored together.

정상 인식Good recognition 비슷한 음량과 환경에서 자막이 정확하게 나온 기준 시점을 남길 때 누릅니다.Use as a good reference when recognition is correct under similar volume and conditions. 문제 시점과 비교하면 값을 너무 공격적으로 낮추거나 높이는 것을 피할 수 있습니다.Compare it with issue markers to avoid tuning thresholds too aggressively.

7. 방송 종료 후 검증 보고서 읽는 방법7. Read the post-broadcast validation report

  1. 가능하면 자막 창에서 Ctrl+C로 정상 종료한 뒤 START_HERE의 6번 최신 방송 검증을 실행합니다. `VALIDATE_LATEST_BROADCAST.bat`를 직접 실행해도 같습니다.Prefer stopping captions with Ctrl+C, then choose START_HERE option 6 Validate latest broadcast. Running `VALIDATE_LATEST_BROADCAST.bat` directly does the same thing.
  2. 결과는 최신 `logs\방송세션` 폴더의 `validation_report.md`와 `validation_report.json`에 저장됩니다. Markdown은 사람이 읽는 요약이고 JSON은 세부 분석용입니다.Results are written as `validation_report.md` and `validation_report.json` in the latest session log folder. Markdown is the readable summary; JSON contains detailed metrics.
  3. 보고서는 첫 자막 시간, STT 평균·P50·P95·최대 지연, 메모리 증가, GPU 사용률, 엔진 오류, 복구 실패, JSONL과 SQLite 자막 일치, 사용자가 표시한 문제를 함께 검사합니다.The report checks first-caption time, STT average/P50/P95/max latency, memory growth, GPU use, engine errors, recovery failures, JSONL/SQLite parity, and user markers.

7-1. 환각·누락·지연·멈춤 조정 순서7-1. Tune hallucination, misses, latency, and stalls

  1. 환각이 반복될 때: 먼저 당시 자막을 /validate에서 환각으로 표시합니다. 실시간 처리의 환각 차단 기준을 0.72→0.67로 한 단계만 낮추고 방송을 재시작합니다. 그래도 배경음에 반응하면 오디오의 Silero 음성 기준을 0.50→0.53으로 올립니다.Repeated hallucinations: Mark the caption in /validate, lower the hallucination threshold from 0.72 to 0.67, and restart. If background audio still triggers captions, raise Silero from 0.50 to 0.53.
  2. 안녕하세요 같은 짧은 말이 빠질 때: 짧은 발화 보호 길이를 12→16으로 올립니다. 여전히 빠지면 Silero 음성 기준을 0.50→0.47로 낮추고 시작 여유 시간을 0.3→0.5초로 늘립니다. 환각 기준과 VAD를 동시에 여러 단계 바꾸지 마세요.Short greetings are missed: Raise short-speech protection from 12 to 16. If needed, lower Silero from 0.50 to 0.47 and raise pre-roll from 0.3 to 0.5 seconds. Change one step at a time.
  3. 자막이 늦을 때: 최신 검증 보고서의 STT P95와 미리보기 대기 압력을 확인합니다. P95가 목표 4초를 넘으면 청크를 0.2초 줄입니다. 교체·건너뜀 수가 기준보다 높으면 갱신 간격을 0.1초 늘리거나 임시 자막 요청을 줄입니다.Captions are late: Review STT P95 and preview pressure. If P95 exceeds 4 seconds, reduce chunk length by 0.2 seconds. If preview pressure is high, raise debounce by 0.1 seconds or reduce preview requests.
  4. 인식이 멈출 때: 프로세스 모드에서는 heartbeat가 끊기거나 작업이 제한 시간을 넘으면 STT만 재시작하고 확정 음성을 다시 처리합니다. 보고서에 STT 재시작 또는 복구 실패가 있으면 30분 테스트 후 7번 지원 묶음을 만듭니다.Recognition stalls: Process mode restarts STT when heartbeat or job limits fail and replays confirmed audio. If the report shows STT restarts or failed recovery, run a 30-minute test and build a support bundle with option 7.

7-2. 방송 분석 조정 사용법7-2. Tune broadcast analysis

  1. 처음에는 균형: 분석 탭에서 균형 프리셋을 채우고 저장합니다. 이 설정은 STT나 실시간 자막 속도를 바꾸지 않습니다.Start balanced: Fill and save the Balanced preset. Analysis settings do not change STT or live caption speed.
  2. 요약이 너무 길면: 요약 문장 수를 5에서 3~4로 낮춥니다. 중요한 내용이 빠지면 6~7로 올립니다.Summary too long: Lower bullets from 5 to 3–4. Raise to 6–7 if useful details are missing.
  3. 주제 전환이 너무 많으면: 전환 민감도를 낮추고 비교 창과 대기 시간을 올립니다. 반대로 전환을 놓치면 민감도를 올리고 창을 줄입니다.Too many topic changes: Lower sensitivity and increase window and cooldown. Reverse those changes when transitions are missed.
  4. 하이라이트가 엉뚱하면: 자주 오탐되는 신호의 가중치만 0.05~0.1씩 낮춥니다. 웃긴 장면을 더 찾으려면 웃음 표현, 전환 직후 장면을 더 찾으려면 주제 전환 근처를 올립니다.Poor highlights: Lower only the noisy signal by 0.05–0.1. Raise Laughter for funny moments or Near topic change for transition moments.
  5. 확인: 저장 후 방송 기록 또는 30분 요약을 다시 열면 캐시가 지워지고 새 설정으로 즉시 계산됩니다.Review: Reopen History or Summary after saving. Cached analysis is cleared and recalculated immediately.

8. 방송 기록과 아카이브 관리8. Broadcast archive management

  1. 기록 보기: 상단 `방송 기록`을 엽니다. 고급 메뉴가 필요하면 START_HERE의 8번으로 들어갈 수 있습니다. 방송 선택, 자막 검색, 30분 구간, 요약, 주제 전환, 하이라이트 후보와 다시보기 시점을 확인할 수 있습니다.View records: Open History from the top bar. Advanced tools remain under START_HERE option 8. You can select broadcasts, search captions, inspect 30-minute windows, summaries, topic changes, highlights, and VOD offsets.
  2. 전체 아카이브 백업: 현재 SQLite 방송 기록 전체를 `reports\archive_backups` 아래 ZIP으로 저장합니다. 이 ZIP에는 자막 내용이 있으므로 외부 전달 전 개인정보를 확인하세요.Full archive backup: Saves the complete SQLite archive as a ZIP under `reports\archive_backups`. It contains caption text, so review privacy before sharing it.
  3. 기간 정리: 입력한 일수보다 오래된 `종료된 방송`만 SQLite에서 삭제합니다. 예를 들어 90은 90일보다 오래된 종료 방송을 뜻합니다. 삭제 전에 전체 백업이 자동 생성됩니다.Retention cleanup: Deletes only ended broadcasts older than the entered number of days. For example, 90 means ended sessions older than 90 days. A full backup is created first.
  4. 선택 방송 삭제: 선택한 종료 방송 한 개를 SQLite에서 삭제합니다. 실행 중인 열린 방송은 삭제할 수 없으며, 삭제 전 백업이 자동 생성됩니다.Delete selected broadcast: Deletes one selected ended session from SQLite. An open live session cannot be deleted, and a backup is created first.
  5. 삭제 범위: 기간 정리와 선택 삭제는 SQLite의 방송·자막·검증 표시를 정리합니다. `logs\방송세션`의 원본 JSONL·메모리·보고서 파일은 자동 삭제하지 않습니다.Deletion scope: Cleanup removes SQLite sessions, captions, and markers. Raw JSONL, memory, and report files under `logs\session` are retained.

업데이트 ZIP은 `data\transcripts.sqlite3`를 포함하거나 덮어쓰지 않으므로 기존 방송 기록은 유지됩니다.Update ZIPs do not include or overwrite `data\transcripts.sqlite3`, so existing archive data is preserved.

9. 강제 종료되거나 음성 인식이 멈춘 뒤의 복구9. Recovery after a force stop or stalled recognition

  1. PC 종료, 창 강제 닫기 또는 Python 종료로 세션이 정상적으로 닫히지 않아도 다음 자막 실행이나 START_HERE의 6번 검증 때 열린 세션을 자동 점검합니다.After a shutdown, forced window close, or killed Python process, the next caption run or START_HERE option 6 validation checks orphaned open sessions.
  2. 기록된 프로세스가 아직 살아 있으면 절대 건드리지 않습니다. 프로세스가 종료된 세션만 마지막 자막 시각으로 닫고 `unclean_shutdown_recovered` 복구 표시를 남깁니다.A session whose process is still alive is never touched. Only dead-process sessions are closed at the last caption time and marked `unclean_shutdown_recovered`.
  3. 로그 폴더가 남아 있으면 방송 보고서도 다시 만듭니다. 다만 강제 종료 직전에 처리 중이던 음성 자체를 복원하는 기능은 아니며, 드롭된 작업 수는 검증 보고서에서 확인합니다.If the log folder exists, the broadcast report is regenerated. Audio still being processed at the instant of termination cannot be restored; dropped jobs are reported instead.
  4. 음성 인식이 반복해서 멈추면 값을 여러 개 바꾸지 말고 START_HERE의 1번으로 한 번 재시작한 뒤 6번 검증을 실행합니다. FAIL 또는 반복 재시작이 보이면 7번 지원 묶음을 만듭니다.If recognition repeatedly stalls, restart once with START_HERE option 1, then run option 6. Build an option 7 support bundle when FAIL or repeated restarts appear.

10. Codex에 분석 자료를 전달하는 가장 좋은 순서10. Best workflow for sending diagnostics to Codex

  1. 실제 방송 또는 10~30분 테스트 중 `/validate`에서 문제 시점을 표시합니다. 오인식은 `실제 발화 / 나온 자막`, 누락은 실제 발화와 목소리 크기, 환각은 당시 배경음을 메모합니다.During a real or 10–30 minute run, mark issues in `/validate`. Note `actual speech / caption` for wrong words, the actual phrase and volume for misses, and background sound for hallucinations.
  2. 자막을 종료하고 START_HERE의 6번으로 검증 보고서를 만듭니다.Stop captions and choose START_HERE option 6 to build the validation report.
  3. START_HERE의 7번으로 `streamer_caption_v2_support_*.zip`을 만듭니다. 최신 설정, 보고서, 세션 로그가 들어가며 원본 음성과 SQLite 전체 DB는 기본적으로 포함하지 않습니다.Choose START_HERE option 7 to create `streamer_caption_v2_support_*.zip`. It includes current settings, reports, and session logs, but not raw audio or the complete SQLite database by default.
  4. 특정 발음 자체를 들어야 하는 문제라면 그때만 짧은 녹음 파일을 별도로 전달합니다. 검증 표시가 있는 로그와 녹음을 함께 주면 원인 구분이 가장 정확합니다.Provide a short recording separately only when the pronunciation itself must be heard. A marked log plus audio gives the most reliable diagnosis.
